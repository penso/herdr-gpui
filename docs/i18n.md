# Internationalization Plan

Herdr UI should be ready to run in any language, including Chinese and
Hebrew, before any translation ships. Only English (`en-US`) message files
are added for now. This document records the decisions and the phased plan;
each phase ends in its own pull request.

## Survey

- **Zed** has no internationalization: no catalogs, no locale handling, every
  string a literal. GPUI has no layout direction concept.
- **gpui-kit** uses `rust-i18n` with one YAML file holding every language per
  key (`crates/component/locales/ui.yml`, `rust_i18n::i18n!("locales",
  fallback = "en")`, `gpui_kit::set_locale`). It has no plural rules and no
  bidirectional isolation.
- **GPUI text** already shapes bidirectional text (CoreText on macOS,
  cosmic-text with `unicode-bidi` on Linux) and wraps CJK text without spaces
  (`LineWrapper`). The Windows DirectWrite path passes `bidiLevel: 0`, so RTL
  shaping there must be verified.
- **Herdr UI today**: about 1,700 Rust files and 409k lines with inline
  literals, `&'static str` command labels in `herdr-commands`, hand-built
  relative times (`herdr-vcs/src/checkpoint.rs`), about 27 hand-built plurals,
  and `thiserror` messages shown to users.

## Decisions

| Question | Decision |
| --- | --- |
| Message format | [Project Fluent](https://projectfluent.org) (`.ftl`): CLDR plural and gender selectors live in the translation, and placeables are wrapped in Unicode isolation marks (FSI/PDI) so Hebrew text stays readable around Latin names. |
| Rust stack | `fluent-bundle`, `fluent-langneg`, `unic-langid`, through `i18n-embed`'s loader. `fl!` checks message IDs and arguments against the English files at compile time, as `i18n-embed-fl` does for System76's COSMIC desktop, but is the app's own: `i18n-embed-fl` reads one `.ftl` file per language, and every feature keeps its own file (see Layout). |
| System locale | `sys-locale`, negotiated against available locales with `fluent-langneg`, falling back to `en-US`. |
| Formatting | Fluent `NUMBER()` and plural selectors first; ICU4X (`icu` 2.x) only where a formatter is genuinely needed (dates, lists). |
| Alternatives rejected | `rust-i18n` (no plurals or isolation; still driven via `gpui_kit::set_locale` if gpui-kit lands), gettext (weak plural model, English-as-key), MessageFormat 2 (no production-ready Rust implementation yet; revisit later). |
| Error messages | Translated. Typed errors keep their `thiserror` English `Display` for logs; users see a localized message chosen by variant at the presentation boundary. |
| Translations shipped | English only. Pseudo-locales are generated at runtime for testing, never written as files. |

## Scope

Translated: command labels, menus, the settings window, dialogs, tooltips,
the status bar, empty states, notifications the app writes, relative times,
and user-facing error messages.

Never translated: terminal content, text from the daemon, agents, Git, or
GitHub; names users chose (workspaces, branches, hosts); config keys and
command `name`s; `--json` output and its keys; logs, diagnostics, and crash
reports; commit messages and other text the app writes into repositories;
CLI `--help` (deferred).

## Layout

```text
crates/herdr-i18n/                   no GPUI
  src/lib.rs                         exports
  src/locale.rs                      Locale, Direction, Pseudo, Language
  src/negotiate.rs                   system languages, negotiation (fallback en-US)
  src/catalog.rs                     the loader over embedded feature files
  src/pseudo.rs                      en-XA / en-XB transforms
  src/error.rs                       Error, Result
crates/herdr-gpui/locales.rs         build script: embeds and checks the files,
                                     writes the table fl! checks against
crates/herdr-gpui/src/i18n.rs        fl!, the current catalog, the GPUI locale global
crates/herdr-gpui/locales/en-US/     one .ftl file per feature module
  commands.ftl
  palette.ftl
  ...
```

- One `.ftl` file per feature module, message IDs prefixed by the feature
  (`worktree-popover-delete = Delete`). New features add a new file, so
  parallel pull requests do not edit a shared catalog.
- Message IDs are stable identifiers, not English text. Changing an English
  string's meaning means a new ID.
- Messages take named arguments only; never concatenate translated fragments
  or build sentences in Rust.
- `fl!("palette-count", shown = 3, total = 9)` formats a message in the
  current locale. A call naming no English message, an argument the message
  does not take, or leaving one out fails to compile at that call. Code that
  picks a message ID as data, as the command catalog does, calls
  `i18n::message` instead, and a test checks its table against the English
  files.
- The build script refuses a file that does not parse, an ID without its
  file's prefix, or one defined twice in a language. `just check-i18n` also
  fails on an English message nothing uses.

## Phases

### Phase 0 + 1: Foundation and pseudo-locales (one PR)

- Add `crates/herdr-i18n`: `Locale` (a `LanguageIdentifier`),
  `Direction { Ltr, Rtl }` derived from the locale's script (Hebrew, Arabic,
  Persian, Urdu, ...), negotiation with `en-US` fallback, an embedded loader,
  and its own `Error`/`Result`.
- Config `language = "system"` (default) or a BCP 47 tag. The current locale
  is a GPUI global; changing it refreshes every window. Add a
  `herdr-gpui` CLI command to read and set it, per the command-line rules
  (`herdr-gpui language`, `language list`, `language set TAG`).
- `fl!` in `herdr-gpui` with compile-time checked IDs and arguments.
- Pseudo-locales through Fluent's transform hook: `en-XA` (accented, about
  40% longer, bracketed) and `en-XB` (right-to-left, `Direction::Rtl`).
  Selectable from the QA menu next to Slow Animations.
- Headless leak test: render the main views under `en-XA` and fail on any
  visible text run without the pseudo markers (allowlisting untranslated
  data such as terminal cells and user names).
- `just check-i18n` in `just ci`: `.ftl` files parse, no duplicate or unused
  IDs, every `fl!` ID exists in `en-US`.
- Migrate one module end to end as the template: the command catalog
  (`herdr-commands` labels become message IDs; the palette matches both the
  translated and the English label), and the command palette's own text, the
  first surface the leak test covers. Command line output and `--json` keep
  the English names.

### Phase 2: String migration

- Move every user-visible string in `herdr-gpui` to `.ftl`, one feature
  module per commit (or per PR when large).
- Replace hand-built plurals and relative times with Fluent selectors.
- Error messages: add a localized display for each user-facing error enum,
  matching on variants, nesting through wrapped crate errors
  (`GitHub(#[from] herdr_github::Error)` delegates to that crate's mapping),
  with English `Display` kept for logs.
- Once a module is migrated, mark it so `just check-i18n` rejects new bare
  literals in its render code.
- Goal: the `en-XA` leak test passes for every window and popover.

### Phase 3: CJK readiness

- UI font fallback chain per platform for CJK (PingFang SC/TC, Hiragino,
  Microsoft YaHei/JhengHei, Noto Sans CJK), separate from the terminal's
  fallbacks.
- Verify IME composition (Pinyin, Zhuyin, Japanese) in dialogs, search,
  settings, and the sidebar, including popup placement.
- Truncation and ellipsis never split a grapheme cluster; layouts tolerate
  both shorter (CJK) and longer (`en-XA`) labels.

As built: `herdr_i18n::CjkScript` reads which regional Han glyphs a
language wants (Simplified, Traditional, Hong Kong, Japanese, Korean), and
`config/cjk_fonts.rs` holds each platform's families. When a face's
`fallback` is unset, the sidebar, tab, and interface faces search the
installed icon fonts, then one installed CJK family per script, the script
of the first CJK language in the `language` setting or the system's
languages first; the setting counts before any translation in that
language ships. The terminal keeps the icon cascade alone. The app's own
cuts (`truncate.rs`) count grapheme clusters, or columns where the budget
is a width, and SearchInput's arrows and deletion step over whole clusters
as DialogInput's already did. GPUI's width-based `text_ellipsis` still
cuts between `char`s inside GPUI; CJK text is unaffected, but a combining
mark or emoji sequence at the cut can lose its tail there.

### Phase 4: Right-to-left

- Layout direction helpers in `herdr-gpui`: logical start/end padding,
  margins, borders, and alignment; rows that reverse under `Direction::Rtl`;
  mirrored directional icons (chevrons, back/forward); sidebar side,
  popover anchors, and animation directions flip.
- The terminal grid and its content always stay left-to-right.
- Verify per platform: FSI/PDI isolation marks render with zero width and
  no missing-glyph boxes; DirectWrite shapes RTL runs (`bidiLevel`); caret
  movement and selection in mixed-direction text inputs.
- Validate everything with `en-XB` until a real Hebrew file exists.

### Phase 5: Platform and documentation

- macOS `Info.plist`: `CFBundleDevelopmentRegion` and
  `CFBundleLocalizations` so system-provided menu items follow the locale.
- Windows installer and Linux desktop entry: localizable display strings.
- Settings > General: a language picker listing available locales by their
  own names (endonyms), plus "System".
- Contributor guide (this file's successor): adding a message, running the
  pseudo-locales, and adding a language as a new `locales/<tag>/` directory.
